# 每日汇报：云端持久化说明

v0.2 使用独立 daily_reports 表保存数据；用户已执行 daily_reports.sql。
填写后需明确点击“保存到云端”。尚未保存的修改只保留在页面内存中。
匿名请求已验证返回 401 / permission denied；用户已确认保存、刷新读取测试成功。
跨账户、跨设备冲突的实际集成测试尚未执行。

## 已实现的交互

- 每日四个部分：工作计划、提交资料、寻求帮助、会议预约。
- 工作计划始终展开；其他三项默认否，选是展开一条，可逐条增加。
- 切换为否只隐藏、不清除输入；汇报视图不展示隐藏事项。
- 各事项具有完成勾选；今天可以复制昨天启用部分的非空未完成事项。
- 复制不修改昨天，不覆盖今天已有内容，以来源标识去重。
- 可选择日期从云端查看历史；口头视图按四部分列出。

## 数据模型与权限

新增独立 daily_reports 表，不修改已有 private_items 记录。
以 (user_id, report_date) 唯一约束保证每天一份；四个部分保存为经校验的 JSONB。
保存事项 ID、内容、完成标记、来源 ID 以及部分启用状态。
启用并强制 RLS，撤销 anon 和 PUBLIC 权限；authenticated 仅可操作 auth.uid() = user_id 的记录。
INSERT/UPDATE 使用 WITH CHECK 防止伪造或转移归属。
实现加载、保存、错误重试及未保存切换提示，不以浏览器存储冒充云端保存。
revision 字段由数据库触发器维护；更新必须匹配读取时的版本，冲突保留本地输入并提示用户。
建表脚本只执行一次，不需要每次发布重新执行。
